# 3. Requisitos

Esta seção projeta, no formato da disciplina, os **129 requisitos funcionais** definidos na fonte de verdade (`docs/orquestador/REQUISITOS.md`). Os IDs são preservados para rastreabilidade.

**Prioridade:** Essencial (E) · Desejável (D) · Opcional (O).
**Plataforma:** *web e mobile* (no escopo dos dois clientes) · *mobile* (só o app) · *backend/sistema* (sem interface direta).
**Status:** todos *A iniciar* — o projeto está no período-0; o status por feature é acompanhado em `docs/plano-de-desenvolvimento/`.

## 3.3. Restrições Arquiteturais

As restrições impostas ao projeto que afetam sua arquitetura são:

- O aplicativo **mobile** deve ser desenvolvido em **Flutter nativo**; **Flutter Web é vetado**.
- A aplicação **web** deve ser uma **SPA em Vue + Tailwind CSS**.
- O backend deve seguir **arquitetura de microsserviços**, implementados em **Spring (Java)** e **NestJS (TypeScript)**.
- A comunicação entre clientes e serviços deve ser **HTTP/JSON**, com contrato em **OpenAPI**; integração entre serviços jamais por acoplamento de tipo/biblioteca.
- A persistência deve usar **PostgreSQL hospedado no Neon**, com **um schema por serviço** (separação lógica).
- O processamento assíncrono deve usar **RabbitMQ** (CloudAMQP).
- Serviços e site estático devem ser hospedados no **Render**, em plano gratuito (implica tratar hibernação).
- Serviços de apoio restritos a planos gratuitos: **Cloudinary** (imagens), **Brevo** (e-mail), **FCM** (push Android), **GitHub Actions** (agendamento e CI/CD).
- **Firebase** é usado **exclusivamente** para FCM; nenhum dado de domínio no Firestore.
- Idioma **pt-BR**; internacionalização fora de escopo.
- Cadastro restrito a **maiores de 18 anos** (LGPD).
